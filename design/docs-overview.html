cms-lab documentation

cms-lab is a CLI that scans your headless CMS content against your Next.js routes and tells you what will break before you deploy. This page covers how it works, what to install, and how to run your first scan.

How it works

cms-lab is config-first. You declare your CMS provider and a small set of route patterns. The CLI then fetches your documents, resolves their expected URLs, probes your local or staging site, and runs a fixed set of content + accessibility + SEO checks against the result.

There is no cms-lab service, dashboard, or account. Everything runs against the CMS credentials already in your .env, and output is either terminal, JSON, or a static report.html you can open or upload as a CI artifact.

Heads up

cms-lab does not test rendered DOM, performance, or runtime errors. It validates the contract between your CMS and your routes. Pair it with Playwright/Lighthouse for the rest.

Install

Install per-project so version pinning lives in your lockfile:

pnpm add -D @cms-lab/cli @cms-lab/next @cms-lab/prismic

Or run ad-hoc with no install:

npx cms-lab scan

Requires Node ≥ 18. Works with pnpm, npm, yarn, and bun.

Configure

Add a cms-lab.config.ts at the root of your project. Most projects need fewer than 30 lines. 

// cms-lab.config.ts
import { defineConfig } from '@cms-lab/core'

export default defineConfig({
  site: { url: 'http://localhost:3000' },

  framework: {
    type:   'next',
    router: 'app',
  },

  cms: {
    provider:       'prismic',
    repositoryName: 'my-agency-cms',
    accessToken:    process.env.PRISMIC_ACCESS_TOKEN,
  },

  routes: [
    { type: 'page',      pattern: '/:uid',       getPath: (d) => `/${d.uid}` },
    { type: 'blog_post', pattern: '/blog/:uid', getPath: (d) => `/blog/${d.uid}` },
  ],

  checks: {
    seo: { metaDescription: true, ogImage: true },
    a11y: { imgAlt: true },
    links: { internal: true },
  },
})

Config options

KeyTypeDescription
site.urlstringThe URL cms-lab probes. Override at runtime with --url.
framework.type'next'Next.js is supported. Astro and Remix are tracked.
framework.router'app' | 'pages'How cms-lab matches your routes to file-system segments.
cms.provider'prismic' | 'strapi' | 'shopify'Which adapter loads documents. Strapi is planned, Shopify is planned.
routes[]Route[]How each content type maps to a URL. The source of truth for route checks.
checks.*objectToggle individual check groups. All default to true.

Your first scan

Boot your Next.js dev server, then run:

pnpm dev &
npx cms-lab scan

You should see something like this:

first scan · zsh 
$ npx cms-lab scan

cms-lab
✓ config loaded         cms-lab.config.ts
✓ cms reachable         prismic · 142 docs
✓ probing 142 routes    http://localhost:3000

  warnings  2
  info      0

Output formats

cms-lab can emit results in three formats. Combine as needed.

FlagOutputUse it for
--pretty (default)Grouped terminal outputLocal development
--jsonScanResult JSON to stdoutCustom tooling, dashboards
--report.cms-lab/report.htmlCI artifacts, PR review

Use it in CI

Add a step that runs after your build. cms-lab exits non-zero on errors, so failed scans block your pipeline by default.

# .github/workflows/cms.yml
name: cms-lab
on: [pull_request]

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v3
      - run:  pnpm install
      - run:  pnpm build && pnpm start &
      - run:  npx wait-on http://localhost:3000
      - run:  npx cms-lab scan --ci --report
      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: cms-lab-report
          path: .cms-lab/report.html
Tip

Use --ci instead of --pretty in pipelines. It disables spinners, colorizes for plain text, and emits annotations GitHub can parse.
