cms-lab scan

Fetch CMS documents, resolve their expected routes, probe your site, and run all enabled checks. The default — and only — command you’ll need most days.

Synopsis

npx cms-lab scan [options]

With nothing else, scan reads cms-lab.config.ts from the current directory, hits the configured site URL, and prints a grouped summary.

Quick examples

# run against your local dev server
npx cms-lab scan

# run against staging instead
npx cms-lab scan --url https://staging.example.com

# filter to a single content type
npx cms-lab scan --type blog_post

# emit JSON for CI
npx cms-lab scan --ci --json > cms-lab.json

# write a static HTML report and open it
npx cms-lab scan --report

Options

FlagDefaultDescription
--url <url> config.site.url Override the URL cms-lab probes. Useful for staging, previews, or running against a static export over file://.
--config <path> cms-lab.config.ts Path to an alternate config file. Supports .ts, .js, .mjs.
--type <type> all Limit the scan to a single CMS content type. Repeatable.
--only <check> all Run a single check group (routes, seo, a11y, images, fields).
--skip <check> none Inverse of --only. Repeatable.
--json false Print a ScanResult JSON object to stdout instead of the pretty summary.
--report false Write a static .cms-lab/report.html in addition to terminal output.
--ci false CI mode. Disables spinners, prints stable output, and emits GitHub-style annotations.
--fail-on <sev> error Severity threshold for a non-zero exit. One of error, warning, never.
--concurrency <n> 8 Parallel route probes. Lower if your local server gets cranky.
--timeout <ms> 5000 Per-route HTTP timeout.
--no-color auto Disable ANSI colors. Inherits FORCE_COLOR / NO_COLOR.
-h, --help Print help and exit.

Exit codes

CodeMeaning
0Scan completed and is under the --fail-on threshold.
1Diagnostics at or above the threshold (default: any error).
2Config error — missing or invalid cms-lab.config.ts.
3CMS unreachable or auth failed.
4Site unreachable — --url never responded within the timeout.
130Interrupted (SIGINT).

Output

In --pretty mode (default), diagnostics are grouped by check family. Each line shows severity, check code, message, and the responsible CMS document.

JSON shape

With --json, cms-lab writes a single ScanResult object to stdout. Stable across patch versions.

{
  "project": {
    "framework": "next",
    "router":    "app",
    "cms":       "prismic",
    "url":       "http://localhost:3000"
  },
  "documents": 142,
  "diagnostics": [
    {
      "severity": "error",
      "code":     "CMS-ROUTE-404",
      "message":  "Route /blog/old-launch-post returned 404",
      "path":     "/blog/old-launch-post",
      "source":   "prismic:blog_post#H1qP"
    }
  ],
  "summary": { "errors": 7, "warnings": 9, "info": 0 }
}

Check codes

Each diagnostic has a stable code. Use them with --only, --skip, or for filtering in your own tooling.

CodeSeverityGroupMeaning
CMS-ROUTE-404errorroutesA CMS document’s expected URL returned 404.
CMS-ROUTE-500errorroutesA CMS document’s expected URL returned a 5xx response.
CMS-ROUTE-SLOWwarningroutesRoute responded over the configured slow-threshold (default 2.5s).
CMS-FIELD-MISSINGerrorfieldsA required field is missing or empty.
CMS-LINK-DEADerrorlinksAn internal CMS link points to a document that doesn’t exist.
SEO-META-MISSINGwarningseometa_title or meta_description is blank.
SEO-OG-IMAGEwarningseoog_image field is empty.
A11Y-IMG-ALTwarninga11yAn image field is missing alt text.
Tip

Run npx cms-lab explain CMS-ROUTE-404 for a longer description, common causes, and a fix snippet for any check code.
