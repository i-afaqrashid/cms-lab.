Catch CMS bugs before deploy.

cms-lab scans your headless CMS content against your Next.js routes and reports broken pages, missing SEO fields, and bad image alt text — locally, in CI, or wherever you ship from.

02 · Checks

What cms-lab looks for.

/_

Route reachability

Resolves every CMS document to its expected URL, probes your local site, and flags 404s, 500s, and redirects you didn’t expect.

code: CMS-ROUTE-404
{}

Required fields

Validates documents against your config so missing UIDs, broken relations, and empty required fields surface before they hit prod.

code: CMS-FIELD-MISSING
</>

SEO completeness

Catches blank meta titles, missing meta descriptions, OG image gaps, and short or duplicate slugs across content types.

code: SEO-META-MISSING
[a]

Image alt text

Walks every CMS image field and flags missing or placeholder alt text — including nested slices and repeatable groups.

code: A11Y-IMG-ALT
⇄

Internal links

Resolves CMS link fields and rich-text links, then checks the target document still exists and resolves to a real route.

code: CMS-LINK-DEAD
CI

CI-friendly output

Exits non-zero on errors, emits JSON for annotations, and produces a single static report.html you can upload as an artifact.

code: --ci · --json · --report
03 · Setup

Drop it into a Next.js + headless CMS project.

1. Install

# add the CLI to your project
pnpm add -D @cms-lab/cli @cms-lab/next @cms-lab/prismic

# or just run it
npx cms-lab scan

2. Configure

// cms-lab.config.ts
import { defineConfig } from '@cms-lab/core'

export default defineConfig({
  site:      { url: 'http://localhost:3000' },
  framework: { type: 'next', router: 'app' },
  cms: {
    provider:       'prismic',
    repositoryName: 'my-agency-cms',
    accessToken:    process.env.PRISMIC_ACCESS_TOKEN,
  },
  routes: [
    { type: 'page',      pattern: '/:uid',        getPath: (d) => `/${d.uid}` },
    { type: 'blog_post', pattern: '/blog/:uid',  getPath: (d) => `/blog/${d.uid}` },
  ],
})

3. Scan

npx cms-lab scan
npx cms-lab scan --url https://staging.example.com
npx cms-lab scan --ci --json > cms-lab.json

Use it in CI

Exits non-zero on errors, writes JSON to stdout, and uploads a single report.html as an artifact. No hosted cms-lab service.

# .github/workflows/cms.yml
- run: pnpm build && pnpm start &
- run: npx wait-on http://localhost:3000
- run: npx cms-lab scan --ci --report
- uses: actions/upload-artifact@v4
  with:
    name: cms-lab-report
    path: .cms-lab/report.html

FAQ

Boring questions, answered.

Does it need an account or API key?

No. It runs locally against your CMS credentials. There is no hosted cms-lab service or dashboard.

Does it test rendered pages?

It probes the URLs your CMS expects and checks status codes. It doesn’t replace Playwright or Lighthouse — it covers the CMS half.

What if I don’t use Next.js?

The first release ships Next.js-only. The framework adapter is a small interface — Astro and Remix are likely next.
